Sequill: how the code is laid out

A SQLite browser, editor and schema designer. The desktop app is a Tauri window over a native SQLite engine written in Rust, with an MCP server so AI assistants can use the same databases. The same React UI also runs in a browser on the official SQLite WASM build. Two pages: the editor at / and the schema designer at /vis.

How a page reaches SQLite

From opening the app to a query running on a database file. Pages never touch SQLite directly: they go through one client that picks the engine for the build.

Entry

app/main.tsx renders app/app.tsx, which picks the page for the path (lib/router.ts): pages/editor-page.tsx or pages/vis-page.tsx.

Boot

components/templates/app-boot.tsx starts SQLite and downloads the page's UI in parallel, showing each stage.

Feature

features/editor/…/editor-shell.tsx or features/vis/…/vis-shell.tsx: sidebar, tabs, grid and console, or the diagram, outline and inspector.

Hooks & stores

hooks/use-db.ts wraps SQLite calls in React Query; Zustand stores in store/ hold tabs, dialogs and saved queries.

Client

lib/sqlite/client.ts: in the desktop app desktop.ts calls Tauri commands; in a browser worker.ts runs SQLite WASM on OPFS.

Engine

src-tauri/src/commands.rs hands each call to crates/sequill-core (Store, Session), which works on the real files.

How an assistant reaches it (MCP)

One executable: sequill opens the window, sequill mcp is what an assistant starts over stdio.

Assistant

Claude, Cursor, VS Code and others start sequill mcp over stdio.

Relay

crates/sequill-mcp/src/relay.rs passes each call to the open app over a local pipe (pipe.rs).

App host

host.rs runs the tool in the app with SequillServer (server.rs, tools/), checking the MCP switches on every call.

App closed

The relay runs the tool itself on the same data folder; the app's watcher (src-tauri/src/watch.rs) shows the change when it opens. Windows app packages wait for the app instead.

Layers

Each layer may import the ones below it, never one above. Shared components follow atomic design (atomic.config.json): atoms → molecules → organisms → templates → pages.

sqlite-browser-editor · code map

Sequill: how the code is laid out

An offline SQLite browser and editor that runs entirely in the browser. SQLite (official WASM build) runs in a Web Worker and keeps databases in the Origin Private File System, so nothing is uploaded. Three routes: a landing page at /, the editor at /app, and a schema visualizer and designer at /vis. The site ships as a static export with an offline service worker.

How a page reaches SQLite

The path from opening /app or /vis to a query running on a file in OPFS. The landing page loads none of this.

Route

src/app/app/page.tsx and src/app/vis/page.tsx only render EditorBoot / VisBoot.

Boot

components/common/app-boot.tsx starts SQLite and downloads the UI chunk in parallel, showing stages: engine → storage → interface.

Shell

components/app/editor-shell.tsx or components/vis/vis-shell.tsx: the lazily loaded page UI (sidebar, tabs, grid, console / diagram, outline).

Hooks & stores

hooks/use-db.ts wraps worker calls in React Query; Zustand stores in lib/store/ hold tabs, dialogs and saved queries.

Client → worker

lib/sqlite/client.ts creates the worker once and talks to it through Comlink.

Worker & session

lib/sqlite/worker.ts loads WASM from public/sqlite/, installs the opfs-sahpool VFS; session.ts runs SQL with bound parameters.

Layers

Arrows point at what each layer imports. Pure logic in lib/ has no React and is what the unit tests cover.
